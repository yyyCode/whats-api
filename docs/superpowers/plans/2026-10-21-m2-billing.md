# M2 · 计费闭环实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use `- [ ]` for tracking.

**Goal:** 一次转发请求能预扣、结算、失败退款，并发下不超支；消费日志能完整复盘金额是怎么算出来的。

**Architecture:** 整数账本（quota）+ 条件 UPDATE 原子预扣 + 请求级状态机（预扣/结算/退款各自幂等）+ 倍率计费（模型倍率 × 分组倍率）+ 消费日志。M2 只做钱包与令牌额度，不做订阅、缓存倍率、表达式定价、Redis 预扣。

**Tech Stack:** Go 1.23（工具链 1.26.5）、GORM、SQLite/MySQL/PostgreSQL、gin。不引入新依赖。

**分支:** `feat/m2-billing`（从 `main` 的 `c3bf062` 拉出）。

## 决策表（实现时不再讨论）

| 决策 | 结论 | 理由 |
|---|---|---|
| 账本单位 | `int64` quota；1 美元 = 500,000 quota（沿用 M0 的 `common.QuotaPerUnit`） | 浮点记账长期有误差 |
| 倍率语义 | `model_ratio` = **美元 / 100 万输入 token**；`completion_ratio` 是输出相对输入的倍数；`group_ratio` 乘在最终金额上 | 对运营可读；公式简单到能写进日志 |
| 预扣公式 | `prompt × modelRatio / 1e6 × QuotaPerUnit × groupRatio × preConsumeMultiplier`，`Strict` 取整 | 只预扣输入；输出长度调用前未知 |
| 结算公式 | `(prompt + completion × completionRatio) × modelRatio / 1e6 × QuotaPerUnit × groupRatio`，`Checked` 取整 | 与预扣同一套倍率，只差 completion 项 |
| 最小预扣 | 计算结果 > 0 但取整为 0 时抬到 1 quota；倍率配置为 0 的模型允许 0（免费） | 否则便宜模型可无限并发白嫖 |
| 资金源 | M2 只有钱包 + 令牌额度；两者都必须够 | 订阅是后续阶段 |
| 预扣顺序 | 事务内先令牌、后用户；任一失败整体回滚 | 令牌是更具体的限额 |
| 结算差额 | `delta > 0` 无条件补扣（允许负余额）；`delta < 0` 退回差额 | 上游已执行，拒绝补扣等于白送 |
| used_quota | 结算时按 **actual** 累加到用户与令牌 | 只统计成功的用量 |
| 幂等 | `BillingSession` 显式状态机 `init → preConsumed → settled | refunded`，非法转移返回 false | 四个 bool 的组合正确性不可验证 |
| 退款时机 | 同步执行（defer），不另起 goroutine | 停机时不会写到已关闭的连接 |
| 无 usage | **退款 + 写 `LogTypeError` 日志 + 告警**，不按 0 计费、不估算 | 验收标准③明确要求；「零用量是异常信号」 |
| 流式 usage | 流式请求自动向上游补 `stream_options.include_usage=true`；客户端会多收到一个 `choices: []` 的 usage 帧 | 否则所有流式请求都无 usage、全部退款，等于免费。这是有意的行为偏离，写进验收记录 |
| 日志 | 同步写 `LOG_DB`，含完整计费上下文到 `other` 字段 | 账本是审计凭证，不能丢 |
| 定价配置 | 新配置域 `ratio_setting`，倍率表用 JSON 字符串存，`OnRebuild` 解析成原子快照 | 配置注册表只支持基础类型；热路径无锁读 |
| 非法倍率 JSON | 保留上一份快照 + 记 Error 日志（不 panic） | 一次写错的配置不该让服务起不来 |

## 验收标准映射

| 路线图标准 | 覆盖用例 |
|---|---|
| 并发 200 请求打只有 100 次额度的令牌，成功 ≤100、余额不为负 | `TestConcurrentReserveNeverOverdraws`（model 层 200 goroutine）+ `TestConcurrentRelayNeverOverdraws`（HTTP 层） |

- [ ] 估算规则（写进注释，测试钉住）：解析 `messages`；每条消息计 `4 + ceil(内容 rune 数 / 4)`；最后 +3。内容是字符串就计其 rune 数；是数组（多模态）只累计 `type=="text"` 的 `text` 字段（base64 图片不能按字节折算 token）；整体解析失败回退 `ceil(len(body)/4)`；结果最小 1。
- [ ] 公式（美元/百万 token 语义）：

```go
// ratio 的单位是「美元 / 100 万 token」；QuotaPerUnit = 500000 quota / 美元。
preRaw := float64(prompt) * modelRatio * preConsumeMultiplier *
	float64(common.QuotaPerUnit) / 1e6 * groupRatio
settleRaw := float64(prompt+completion*completionRatio) * modelRatio *
	float64(common.QuotaPerUnit) / 1e6 * groupRatio
```

预扣用 `common.QuotaRoundStrict`，结算用 `common.QuotaRoundChecked`；原始值 >0 而结果为 0 时抬到 1（预扣与结算都抬）。
